# Блокировка, навигация и адреса

Изменения подготовлены на основе GitHub `main`, коммит `f650676`. Рабочая копия скачана в `DIID/source`: в исходной локальной папке не было репозитория. На сервер изменения пока не установлены.

## Что изменилось

- При уходе из веб-приложения (`visibilitychange`, `pagehide`, потеря фокуса) синхронно включается непрозрачная защитная заставка. Страницы хранилища размонтируются вместе с порталами фотопросмотрщика. При установленном PIN возврат требует разблокировки. Открытые фотографии, раскрытые поля и несохранённые формы не восстанавливаются; сохранённые записи остаются на месте.
- Возврат страницы из browser back/forward cache также требует PIN. Завершившаяся с задержкой проверка PIN не может отменить более позднюю блокировку. Исправлена обработка клавиатуры: PIN-компонент больше не слушает цифры во время обычной работы.
- Системный выбор файлов переживает размонтирование страницы: выбранное вложение загружается к исходной записи, при этом приложение остаётся заблокированным. Это действует для фотографий кладов, документов и ключей.
- Кнопка «Маршрут» в карточке клада с координатами открывает встроенную карту. По умолчанию маршрут пеший; есть автомобильный режим, текущая позиция и точность GPS, длина и время маршрута, шаги, центрирование на себе и пересчёт. Во время движения маршрут пересчитывается после смещения более чем на 40 м, не чаще раза в 45 секунд.
- Карта показывает точную позицию клада отдельно от конца дорожного маршрута. Если сервис закончил маршрут на ближайшей дороге, остаток отмечается пунктиром и пояснением. Это не обещание проходимости участка.
- Адрес прописки использует прежнее поле `address`. По умолчанию фактический адрес совпадает с ним. Снятая галочка открывает `residential_address`. При возвращении галочки отдельный фактический адрес очищается после сохранения. Старые записи получают `addresses_match=true` без изменения прежнего адреса. Создание, редактирование и просмотр переведены на EN/RU/KK.

## Ограничения iPhone и навигации

Защитная заставка в PWA — мера снижения риска, а не гарантия скрытого снимка в переключателе iOS. Система может сделать снимок до обработки веб-события. [Apple описывает управление снимком через нативный жизненный цикл приложения](https://developer.apple.com/library/archive/qa/qa1838/_index.html); у PWA нет этого нативного обработчика. Для более строгой защиты нужна отдельная iOS-оболочка с управлением снимком, а затем проверка на устройстве.

Нужно проверить на настоящем iPhone: открытый пароль и фотографию при переходе на домашний экран, в переключатель приложений, при блокировке телефона, возврате и выборе фотографии. Автотесты WebKit проверяют обработчики и интерфейс, но не системный снимок iOS.

Геолокация требует HTTPS (либо localhost для разработки) и разрешения браузера. Карта и маршруты работают онлайн и только пока навигация открыта. Блокировка останавливает GPS и отменяет запросы; для продолжения после PIN нужно снова нажать «Маршрут». Голосового ведения, фоновой навигации и офлайн-карт нет.

До нажатия «Маршрут» внешние картографические запросы не выполняются. После нажатия OpenStreetMap получает запросы видимой области карты, а FOSSGIS получает координаты начала и конца маршрута; им не отправляются названия кладов, заметки, фотографии или cookies хранилища. [FOSSGIS сообщает о журналировании запросов](https://routing.openstreetmap.de/about.html). Для конфиденциальных координат можно настроить собственные серверы через `frontend/.env.local` по примеру `.env.example` и пересобрать frontend. Публичные сервисы не гарантируют доступность. Атрибуция и ссылка исправления карты включены, запросы маршрутов ограничены по частоте, предзагрузки тайлов нет.

## Установка обновления

1. Сохранить резервную копию рабочей БД и файлов вложений обычным способом вашей установки.
2. Обновить код backend и выполнить из его окружения `alembic upgrade head`. Новая миграция: `f6a7b8c9d0e1`.
3. В `frontend` выполнить `npm ci` и `npm run build`, затем разместить `frontend/dist` вашим существующим способом и перезапустить backend.
4. Перезагрузить веб-приложение на телефоне и проверить перечисленные сценарии.

В существующем `docker-compose.yml` описаны только БД и backend; сборка и публикация frontend остаются отдельным шагом. Для backend в Docker миграция запускается через `docker compose exec backend alembic upgrade head`.

В Windows desktop используется собственный идемпотентный апгрейд SQLite при запуске: `create_all` сам не добавляет столбцы в существующие таблицы. Политика PIN для Tauri остаётся прежней: блокировка при скрытии в трей.
